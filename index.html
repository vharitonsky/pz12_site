Практична 12 — персональне завдання

Захист автентифікації й архітектури: аналіз JWT і threat modeling межі сервіс↔сервіс (Zero Trust). Введіть свій user-id, виконайте завдання на сторінці та завантажте відповіді для здачі.

Що і як робити

Інструкція однакова для всіх. Токени декодуйте на jwt.io (вставити токен → побачити header і payload). На сторінці вад не позначено.

  1. Аналіз JWT. Для кожного токена визначте ваду: alg=none, слабкий секрет, немає exp, або коректний (еталон).
  2. Правила перевірки JWT. Позначте всі правила коректної перевірки токена на сервері.
  3. Zero Trust. За схемою сервісів позначте контролі для межі сервіс↔сервіс (внутрішні виклики зараз без перевірки токена).
  4. Ключ підпису. Позначте всі правильні практики зберігання й керування ключем підпису токенів.
  5. Мапінг. Кожній auth-атаці зіставте захід, що її зупиняє.
  6. Здача. «Завантажити відповіді (JSON)» → прикріпити до завдання. Самоперевірки немає — оцінює викладач.

Приклад (на сторонніх даних)

Токен із header {"alg":"none"} і порожнім підписом → вада: alg=none (підпис не перевіряється). Токен без claim exp → безстроковий.
Zero Trust: внутрішній виклик Order→Auth без токена → додати mTLS + токен сервісу + deny-by-default.
Ключ підпису: секрет у коді застосунку → вада; правильно — у Vault/KMS, з ротацією й окремими ключами на середовище.
Мапінг: «перебір слабкого секрету HS256» → сильний випадковий секрет + ротація ключа.
